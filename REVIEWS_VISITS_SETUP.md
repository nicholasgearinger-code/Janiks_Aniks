# Customer Reviews and Private Website Visitor Statistics

## Deployment status
GitHub Pages files have been committed. **Both features remain inactive until the SQL migration and public Edge Functions are deployed in Supabase.** Do not assume the new endpoints are live until tested.

## 1. Run database migration
Open Supabase Dashboard > SQL Editor, paste the entire contents of `supabase/reviews-and-visits.sql`, and run it. This creates:
- `customer_reviews`: public reads only **approved** reviews; only Store Manager owner accounts can read/moderate all ratings.
- `site_visit_days`: anonymized browser-per-day records, protected with RLS; no public SELECT.
- `admin_visit_summary()`: returns three private aggregate metrics only to authenticated store admins.

## 2. Set visitor hash secret
In Project Settings > Edge Functions > Secrets, create `VISITOR_HASH_SECRET` with **at least 32 unpredictable characters** generated by a password manager. Do not put this secret in frontend code or GitHub. Existing standard Supabase `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, and `TURNSTILE_SECRET_KEY` must be available to the functions.

## 3. Deploy two Edge Functions
Create/update `review-submit` from `supabase/functions/review-submit/index.ts` and `website-visit` from `supabase/functions/website-visit/index.ts`.

Disable **Verify JWT** for these two narrowly scoped *public* endpoints only. Both enforce allowed origin, validate inputs, and write using the service role. `review-submit` also verifies Cloudflare Turnstile server-side. Keep admin tables and other Edge Functions secured.

## 4. What is live after activation
- Homepage: shows the **three newest approved five-star** reviews, or a neutral empty state. The feature label should always say five-star highlights, not imply all reviews have five stars.
- `reviews.html`: accepts a 1–5 star rating, a display name, review text and Turnstile. Submissions start **pending**. The page shows the latest 100 approved reviews **of every rating**, with a clearly labeled average for the displayed sample.
- Store Manager > Reviews: pending-review badge, approve, reject (spam/inappropriate content), return to pending. Apply moderation rules **equally to positive and negative feedback**; do not reject legitimate negative reviews simply for their rating.
- Store Manager > Overview: visitors today, last 30 days, and since tracking started. These statistics are **estimated unique browsers**, not verified individual people. The same browser on a different device or with cleared storage is counted separately; tracking blockers may undercount.

## 5. Important privacy/security details
- The visitor script uses a random local browser ID, and the function stores only a **salted hash** of that ID, with date; **no name, email, IP address, device fingerprint, or visited URL** is persisted by this feature.
- Update your site privacy notice to disclose the local identifier and visitor analytics, and provide relevant controls for applicable privacy laws.
- Abuse controls: Turnstile protects review submissions, but deploy additional backend rate limits and abuse monitoring before promotion or high-volume usage. A forged request can still spam visitor counts; origin headers alone are not authentication. These totals are operational estimates, **not certified analytics**.
- This is a **store review**, not a verified-purchase review. Don't mark reviewers as verified buyers unless actual purchase checks are implemented.
- Original checkout, Resend acknowledgment emails, and payment systems are unchanged.

## 6. Acceptance checks
1. Submit a genuine 1-star or 5-star review with the form.
2. Confirm it is pending in Store Manager > Reviews and not public yet.
3. Approve it; confirm it appears on `reviews.html`, and 5-star entries only appear on homepage highlights.
4. Verify 1–4-star approved reviews are included on `reviews.html`.
5. Visit different storefront pages in one browser and check it counts once per day, not once per page.
6. Check a second browser/profile; visitor count should increase when the site visits are recorded.
7. Verify visitor counts aren't visible to logged-out customers and anonymous database reads of `site_visit_days` are denied.
8. Verify mobile navigation/scrolling, rating form, and Store Manager review navigation.

Backend work is intentionally staged: code commits do not modify the running Supabase functions or database until you apply these steps.
